# Purpose

This document defines the development principles that guide every part of the Today Master Project.

These rules apply to all modules, repositories, documentation, and future contributors.

---

# Core Principles

1. Analyze before coding.
2. Avoid duplicate implementations.
3. Maintain a single source of truth.
4. Keep the architecture modular.
5. Test every meaningful change.
6. Update documentation together with the code.
7. Record all significant changes in CHANGELOG.
8. Respect user privacy by design.
9. AI never performs external actions without user approval.
10. Every feature must support the long-term product vision.

---

# Development Workflow

Every development task follows the same workflow:

1. Analyze
2. Design
3. Implement
4. Test
5. Document
6. Commit
7. Review

No step should be skipped.

---

# Documentation Rules

Documentation should always reflect the current state of the project.

Main project documents:

- PROJECT_RULES
- ARCHITECTURE
- ROADMAP
- PHASES
- CHANGELOG

Additional documents should be created only when they provide long-term value.

---

- refactor:
- docs:
- test:
- chore:

---

# Phase Management

A phase can only be completed when:

- Objectives are implemented.
- Tests are successful.
- Documentation is updated.
- CHANGELOG is updated.
- No critical issues remain.

---

# Quality Standards

The project should prioritize:

- Simplicity
- Reliability
- Maintainability
- Scalability
- Privacy
- Explainability

Technical decisions should favor long-term sustainability over short-term convenience.
